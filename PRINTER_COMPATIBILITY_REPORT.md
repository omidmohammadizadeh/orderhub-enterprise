# Printer Compatibility Report — Flutter Android App

> Phase H — Production Validation

## Overview

The existing Flutter Android printer app polls OrderHub for pending print jobs and sends them to a connected Bluetooth/USB/WiFi printer. This report confirms the API contract is maintained.

## API Contract (Must Not Break)

### GET /api/v1/printerJobs?shop_code=:locationCode

**Status: IMPLEMENTED** (added in Phase H)

Returns pending print jobs for a location identified by `shop_code`. Falls back to `location.id` if `shopCode` field is not yet populated.

Response shape:
```json
[
  {
    "id": "uuid",
    "type": "RECEIPT",
    "status": "QUEUED",
    "payload": { ... },
    "orderId": "uuid",
    "printerId": "uuid",
    "createdAt": "ISO string"
  }
]
```

### PATCH /api/v1/printerJobs/:id

**Status: IMPLEMENTED** (added in Phase H)

Updates print job status. Accepts `{ "status": "printed" }` (lowercase) or `{ "status": "FAILED", "error": "..." }`.

Response: `{ "id": "uuid", "status": "PRINTED" }`

## Currency Formatting

All monetary values are stored as Decimal in Prisma and passed as JavaScript numbers to the payload. Values are in the currency's smallest unit (pence for GBP). The Flutter app is responsible for formatting (e.g. dividing by 100 and prefixing £).

No formatting changes have been made to the payload structure. GBP safety is preserved.

## Paper Width

The payload itself is format-agnostic — raw text with ESC/POS commands are generated by the worker's printing processor. 58mm and 80mm modes are controlled by the printer configuration (paperWidth field on the Printer model). The Flutter app reads this from the printer record and formats accordingly.

## Backward Compatibility Rule

All new fields added to the payload are **optional** and typed as nullable. Existing fields are never renamed or removed. The Flutter app will not break when receiving payloads with additional optional fields.

## Known Limitations

- `shopCode` field on Location may not be migrated in the database schema yet. The Flutter endpoint falls back to `location.id` as `shop_code` in the interim.
- CloudPRNT (Star Micronics cloud polling) is handled separately via the existing CloudPRNT job status in the DB. The Flutter polling flow is for Bluetooth/USB/LAN printers only.
