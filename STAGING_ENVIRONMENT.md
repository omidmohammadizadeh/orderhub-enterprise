# Staging Environment — Setup & Management

> Last updated: Phase Z — Cloud Deployment & Production Infrastructure (2026-05-19)
>
> This document explains how to bring up the OrderHub staging environment on Render using the
> provided Blueprint (`render.yaml`). No custom infrastructure knowledge required.

---

## What Staging Runs On

| Component | Provider | Notes |
|---|---|---|
| API (NestJS) | Render Web Service | Frankfurt, starter plan |
| Worker (NestJS) | Render Background Worker | Frankfurt, starter plan |
| Web (Next.js) | Render Web Service | Frankfurt, starter plan |
| Database | Supabase (Postgres 15) | External — you connect it via `DATABASE_URL` |
| Redis | Upstash Redis | External — you connect it via `REDIS_URL` / `QUEUE_REDIS_URL` |

---

## Prerequisites

Before starting, you need:

1. A [Render](https://render.com) account
2. A [Supabase](https://supabase.com) project with a Postgres database
3. An [Upstash](https://upstash.com) Redis database (TLS enabled)
4. The OrderHub repository on GitHub

---

## Step 1 — Create External Services

### 1a. Supabase (Postgres)

1. Create a new project at [app.supabase.com](https://app.supabase.com)
2. Choose region: **Frankfurt (eu-central-1)** (same as Render services)
3. Note your project password
4. Go to **Settings → Database → Connection string (URI)**
5. Copy the **pooler** connection string (port 6543):
   ```
   postgresql://postgres.YOURPROJECT:YOURPASSWORD@aws-0-eu-central-1.pooler.supabase.com:6543/postgres
   ```
   Append `?pgbouncer=true&connection_limit=1` for Prisma compatibility.

### 1b. Upstash Redis

1. Create a new database at [console.upstash.com](https://console.upstash.com)
2. Choose region: **EU-West-1 (Frankfurt)** or nearest to Frankfurt
3. Enable **TLS**
4. Copy the **TLS connection URL** (`rediss://default:TOKEN@...upstash.io:PORT`)
5. Use the same URL for both `REDIS_URL` and `QUEUE_REDIS_URL` (one Upstash instance is fine for staging)

---

## Step 2 — Generate Secrets

Run these commands locally and save the output somewhere secure (1Password, etc.):

```bash
# JWT secrets (different for access and refresh)
echo "JWT_SECRET=$(openssl rand -base64 48)"
echo "JWT_REFRESH_SECRET=$(openssl rand -base64 48)"

# Credential encryption key — 64 hex chars
echo "CREDENTIAL_ENCRYPTION_KEY=$(openssl rand -hex 32)"
```

---

## Step 3 — Deploy to Render via Blueprint

1. Push the `render.yaml` file to your GitHub repository (it's in the repo root)
2. Go to [dashboard.render.com](https://dashboard.render.com) → **New** → **Blueprint**
3. Connect your GitHub repository and select the branch you want to deploy
4. Render will detect `render.yaml` and show three services: `orderhub-api`, `orderhub-worker`, `orderhub-web`
5. Click **Apply**

Render will create all three services. Most env vars are already set in the Blueprint. The next step is to fill in the secrets.

---

## Step 4 — Fill in Required Secrets

For each secret variable, go to the service in Render Dashboard → **Environment** → edit:

### orderhub-api

| Variable | Value |
|---|---|
| `DATABASE_URL` | Supabase pooled connection string (Step 1a) |
| `REDIS_URL` | Upstash TLS URL (Step 1b) |
| `QUEUE_REDIS_URL` | Upstash TLS URL (same as above is fine) |
| `CREDENTIAL_ENCRYPTION_KEY` | 64 hex chars from Step 2 |
| `STRIPE_SECRET_KEY` | `sk_test_...` (Stripe test key for staging) |
| `STRIPE_WEBHOOK_SECRET` | `whsec_...` (from Stripe Dashboard → Webhooks) |
| `STRIPE_PUBLISHABLE_KEY` | `pk_test_...` |

> `JWT_SECRET` and `JWT_REFRESH_SECRET` are auto-generated by Render (`generateValue: true` in Blueprint). You do NOT need to enter these manually.

### orderhub-worker

| Variable | Value |
|---|---|
| `DATABASE_URL` | Same Supabase URL |
| `REDIS_URL` | Same Upstash URL |
| `QUEUE_REDIS_URL` | Same Upstash URL |
| `CREDENTIAL_ENCRYPTION_KEY` | **Same key as API** (must match exactly) |

### orderhub-web

| Variable | Value |
|---|---|
| `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` | `pk_test_...` |

---

## Step 5 — Trigger Initial Deploy

1. In Render Dashboard, select **orderhub-api** → **Manual Deploy** → **Deploy latest commit**
2. Watch the logs — you should see:
   ```
   [startup] OrderHub API startup — ...
   [startup] Environment validation passed.
   [startup] Generating Prisma client...
   [startup] Applying database migrations...
   [startup] Migrations complete.
   [startup] Starting OrderHub API...
   [Bootstrap] API running on port 4000 [production]
   ```
3. Deploy `orderhub-worker` — look for `Worker running` in logs
4. Deploy `orderhub-web` — health check on `/` should pass

---

## Step 6 — Verify Health

```bash
# Substitute your actual Render service URL
curl https://orderhub-api.onrender.com/api/v1/health/ready
```

Expected:
```json
{
  "status": "ok",
  "checks": {
    "database": { "status": "ok" },
    "redis": { "status": "ok" }
  }
}
```

If `database` is not `ok`:
- Check `DATABASE_URL` is set correctly on `orderhub-api`
- Check Supabase project is not paused (free tier pauses after inactivity)
- Check IP allowlist in Supabase — Render uses dynamic IPs, so set to "Allow all" for staging

If `redis` is not `ok`:
- Check `REDIS_URL` uses `rediss://` (TLS)
- Check Upstash database is active

---

## Step 7 — Run Smoke Test

```bash
SMOKE_BASE_URL=https://orderhub-api.onrender.com \
SMOKE_TENANT_ID=<your-tenant-id> \
CREDENTIAL_ENCRYPTION_KEY=<your-key> \
DATABASE_URL=<your-supabase-url> \
npx ts-node -P apps/api/tsconfig.json apps/api/src/scripts/smoke-test.ts
```

All checks must pass before staging is considered ready.

## Seeding Staging Data

After first deploy, seed the database:

```bash
# From your local machine with DATABASE_URL set to Supabase staging
DATABASE_URL=<supabase-url> npx ts-node -P apps/api/tsconfig.json \
  apps/api/src/scripts/seed.ts
```

This creates:
- A demo tenant (`demo.orderhubsolutions.com`)
- A demo admin user (`admin@demo.orderhubsolutions.com` / `Demo1234!`)
- A demo location and brand

## Staging vs Production Differences

| Concern | Staging | Production |
|---|---|---|
| Stripe keys | `sk_test_...` / `pk_test_...` | `sk_live_...` / `pk_live_...` |
| Provider credentials | Sandbox | Live |
| `NODE_ENV` | `production` (same) | `production` |
| Render plan | `starter` | `standard` (recommended) |
| Domain | `*.onrender.com` or `staging.*` | `app.orderhubsolutions.com` etc. |
| Supabase tier | Free (may pause) | Pro (always-on) |
| Database backup | Manual | Daily + pre-deploy |

## Troubleshooting

### Service is sleeping / cold start slow

Render free-tier services sleep after 15 minutes. First request wakes them (~30s). To avoid:
- Upgrade to a paid Render account
- Use an uptime monitoring service (Better Uptime, UptimeRobot) to ping `/api/v1/health` every 5 minutes

### `prisma migrate deploy` fails at startup

- Check Supabase project is not paused
- Check `DATABASE_URL` is correct and uses pooled connection
- Check Supabase has the correct Postgres version (15 required)

### Worker not processing jobs

- Check `QUEUE_REDIS_URL` is set and uses `rediss://`
- Check worker logs for `ERROR: QUEUE_REDIS_URL / REDIS_URL not set`
- Both API and Worker must use the **same** Redis instance and the **same** `CREDENTIAL_ENCRYPTION_KEY`

### CORS errors on Web → API

- `SOCKET_CORS_ORIGIN` on the API service must match the Web service URL exactly (no trailing slash)
- Render auto-populates this from `fromService` — double-check the Web service URL in Render Dashboard
